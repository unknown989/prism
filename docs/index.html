2D software renderer · Windows & Linux

A tiny cross‑platform 2D graphics library for C.

Prism gives you a software‑rendered framebuffer, a simple window API, and a set of 2D drawing primitives — all in a tiny C library with no third‑party dependencies.

Demo Spinning up a window

Minimal example using the Prism API:

#include "src/prism.h"

int main(void) {
    prism_size_t size = {800, 600};
    position_t pos = {100, 100};

    window_t *window = create_window(size, pos, 0);
    if (!window) {
        return 1;
    }

    int running = 1;
    while (running) {
        clear_window(window, COLOR_BLACK);

        position_t center = {window->width / 2, window->height / 2};
        circle_t circle = {center, 100};
        draw_circle(window, circle, COLOR_WHITE);

        present_window(window);

        if (is_key_down(KEY_Q)) {
            running = 0;
        }
    }

    free_window(window);
    return 0;
}

Quickstart

Prism ships with a small demo program in examples/demo.c.

Linux

make
./demo

This uses the provided Makefile, which links against libX11 and libm.

Windows

make
demo.exe

On MinGW / clang, the Makefile links against user32 and gdi32.

With MSVC directly:

cl /std:c11 /W4 /Iinclude /Isrc examples\demo.c ^
    user32.lib gdi32.lib
demo.exe

API overview

The public API is declared in include/prism.h and implemented in src/prism.h. Everything revolves around a window_t with an integer pixel buffer.

Core types

  • window_t – window + framebuffer.
  • color_t – RGBA color, 0–255 per channel.
  • position_t – integer 2D coordinates.
  • prism_size_t – integer width/height.
  • rect_t, circle_t, ellipse_t – basic shapes.
  • polygon_t, shape_t – collections of points.
  • image_t, text_t – blitting / text placeholders.

Window functions

  • create_window(prism_size_t, position_t, int)
  • destroy_window(window_t *)
  • free_window(window_t *) (safe wrapper)
  • clear_window(window_t *, color_t)
  • present_window(window_t *)

Drawing

  • draw_pixel, get_pixel
  • draw_line, draw_rect, fill_rect
  • draw_circle, fill_circle
  • draw_ellipse, fill_ellipse
  • draw_polygon, fill_polygon, draw_shape
  • draw_image, load_bmp
  • draw_text (simple built‑in vector font)

Transforms

  • translate(position_t *, int dx, int dy)
  • scale(position_t *, int sx, int sy)
  • rotate(position_t *, int degrees)

Input

Prism includes a small input layer for polling keyboard and mouse state.

  • bool is_key_pressed(key_t key)
  • bool is_key_down(key_t key)
  • mouse_t get_mouse(window_t *window)

On Windows, these are backed by GetAsyncKeyState and Win32 cursor APIs. On Linux/macOS, they currently return default values so your code can still compile and run.

The demo exits when Q is held: if (is_key_down(KEY_Q)) running = 0;

Platform notes

Windows

  • Backend: Win32 window created via CreateWindowEx.
  • Framebuffer blit using StretchDIBits and a 32‑bit DIB.
  • Input handled via GetAsyncKeyState and mouse APIs.

Linux

  • Backend: X11 window via XCreateSimpleWindow.
  • Software blit via XImage and XPutImage.
  • Input helpers are stubbed; extend with your own X11 handling if needed.

macOS

  • Software rendering and API are available.
  • Window presentation and input are currently no‑ops.
  • Intended future direction is a Cocoa/NSView backend.

Design goals

Prism is intentionally small. It is closer to "a framebuffer with helpers" than to a full game engine or UI toolkit.

  • No external libraries – just C, Win32, and X11.
  • Embeddable – easy to bind from other languages.
  • Predictable – software rasterization, no GPU surprises.
  • Single‑header implementation (for now) for easy inclusion.

Future ideas

  • macOS Cocoa backend for native windows.
  • Filled primitives (rectangles, circles, polygons).
  • Basic image loading helpers (PNG/BMP via plug‑ins).
  • Simple bitmap font text renderer.
